0. WHAT THIS PAGE IS
----------------------------------------------------------------
Akinola's technical blog and learning journal. The page should
read as an editorial publication, NOT a generic blog index.
Three things it must do:

  1. Show ONE featured article prominently at the top.
  2. Filter the rest of the articles by category.
  3. Make every row feel like a journal entry, not a blog card.

Reference image: @docs/prototypes/WrittingUI.png
Reference doc:   @docs/WrittingUI.md

----------------------------------------------------------------
1. PAGE FILE
----------------------------------------------------------------
src/pages/writing.js

Default export WritingPage().
State (local — no Redux):
  const [active, setActive] = useState("all");

Derived (useMemo):
  counts   = total + per-category counts from ARTICLES.
  featured = getFeaturedArticle().
  filtered = listArticlesByCategory(active) excluding
             featured.slug.

Head:
  - title "Writing — Akinola Victor"
  - description "Notes on AI engineering, software development,
                 experiments, and lessons learned while building
                 intelligent systems."

Body order:
  <PageShell>
    <WritingHero     active={active} onChange={setActive}
                     counts={counts} />
    <FeaturedArticle article={featured} />
    <ArticleList     articles={filtered} />
    <WritingBio />
  </PageShell>

    - export function getArticleByIssue(issue) { ... }

----------------------------------------------------------------
4. ANIMATION
----------------------------------------------------------------
- Filter pill active transition: 200ms CSS.
- FeaturedArticle: 0.6s ease power2.out on entry, once.
- ArticleList rows: 0.5s × stagger 0.05, once per row.
- Reduced-motion: all gsap calls early-return.

----------------------------------------------------------------
5. RESPONSIVE BEHAVIOR
----------------------------------------------------------------
- < w7: 1 col layout, featured article image is full width
  above the copy, list rows stack.
- w7: 12-col row layout for cards.
- ≥ w9: full layout as described.

----------------------------------------------------------------
6. ACCESSIBILITY
----------------------------------------------------------------
- role="tablist" on the filter pill region, role="tab" on
  each pill, aria-selected={isActive}.
- Each row is an <article> with an h3 title.
- The "Read article →" / "Read →" / "More writing →" links
  are reachable by Tab in source order.
- Featured article's title link is the primary landmark;
  the image is decorative (aria-hidden).

----------------------------------------------------------------
7. DO NOT
----------------------------------------------------------------
- Do NOT add a "subscribe" or "RSS" link — no feed exists.
- Do NOT add a comments section.
- Do NOT add a sort dropdown.
- Do NOT show a date range / month headers — articles are
  ordered by date desc and that is enough.
- Do NOT render the article's full body on the index page;
  the index is the entry point to /writing/[slug].

----------------------------------------------------------------
8. ASSUMPTIONS
----------------------------------------------------------------
- Articles are ordered by `date` desc within the filtered
  list. listArticlesByCategory() already does this; do not
  re-sort in the page file.
- The featured article is the one record with `featured: true`.
  If multiple records have it, pick the most recent. If none
  have it, fall back to the most recent article.
- The article body, code blocks, and pull quotes are NOT
  rendered on the index — they live on /writing/[slug]
  (next prompt).
- "ISSUE NNN" is a display number from the `issue` field on
  each record. It is not an actual journal issue — it is
  a stable chronological index that gives the list a
  publication feel.
- The /writing/[slug] route exists and the rows link there.
  If a slug is missing at build time, the row simply shows
  no link; the page does not break.
