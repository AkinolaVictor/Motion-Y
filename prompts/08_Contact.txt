2.3 ContactForm.jsx (refine)
    Right column of the contact band. Premium, accessible
    form. POSTs to FORM_ENDPOINT (/api/contact), which is
    wired to Resend.

    Fields (in order):
      - Name          (text input, required, autoComplete=name)
      - Email         (email input, required, autoComplete=
                      email, regex validation)
      - What are you working on?  (select, required; options
                      from PROJECT_TYPES — the first option is
                      the disabled "Select one" placeholder)
      - Message       (textarea, required, min 10 chars,
                      rows=5, max-w-full, resize-y, min-h-120)

    Behavior:
      - On submit:
          1. Validate locally. If any field is invalid, set
             errors and stop.
          2. Set status to "sending" and disable the submit
             button.
          3. POST FORM_ENDPOINT with axios (the existing
             component does this — keep the axios import and
             timeout=15000).
          4. On success: set status to "sent", replace the
             form with a success card (the existing component
             already does this — keep the same copy).
          5. On error: surface server-side errors per field
             (payload.fields) OR a generic message. Status
             becomes "error". Keep the user's input.

    Visual structure:
      - Each field is a stacked group (label + input +
        optional error). Field component pattern is already
        in the file (Field, TextareaField, SelectField) —
        keep them, do not duplicate.
      - The submit row has:
          - Left: a small mono caption
              "No spam. No newsletter. Just a reply."
              that turns red on error.
          - Right: a primary Button with a Send icon (a
            simple → svg). When status === "sending", the
            button shows a spinner + "Sending…".

    Animations (≤ 1s total):
      - On scroll into view, fields fade + y in with stagger
        0.08. Honor reduced-motion (the existing component
        already does this).
      - On success, the success card fades in.

    Accessibility:
      - Each field has a real <label htmlFor>.
      - aria-invalid + aria-describedby point at the error
        message when invalid.
      - Submit button: disabled while sending; focus ring
        is visible.
      - The success state uses role="status" so screen
        readers announce the change.

3. DATA USAGE
----------------------------------------------------------------
- src/data/contact.js is the source of truth.
- The four canonical socials (GitHub, LinkedIn, X) and the
  email address are the ONLY contact channels. The contact
  page MUST NOT add Instagram, YouTube, Bluesky, or any other
  link. The Footer and About /social section use the same
  three.
- FORM_ENDPOINT is "/api/contact". The Resend API route
  reads RESEND_API_KEY, RESEND_FROM, CONTACT_TO from env.
- PROJECT_TYPES provides the select options. The first entry
  has value "" and is rendered as a disabled placeholder.

5. RESPONSIVE BEHAVIOR
----------------------------------------------------------------
- < w7: hero centered, single column. Contact band stacks
  vertically (Details on top, Form below). Form fields are
  full width.
- w7 — w8: 12-col grid begins, Details and Form both render
  at full width inside their columns.
- ≥ w9: Details takes 5 cols, Form takes 7 cols.

----------------------------------------------------------------
6. ACCESSIBILITY
----------------------------------------------------------------
- Each <section> has aria-label or aria-labelledby.
- The "copy email" button has aria-label="Copy email" and
  announces the success state via aria-live="polite" on a
  visually hidden span.
- Form: <form noValidate> + onSubmit; submit button is a
  real <button type="submit">.
- The "What are you working on?" <select> has a real
  <label htmlFor>; the placeholder option is disabled.
- Error messages are real <p> elements with text-red-400
  and aria-describedby wiring.
- The form does not auto-focus on mount (auto-focus is a
  screen-reader antipattern).
- The success state ("Thanks — I'll reply soon.") has
  role="status" so it is announced politely.

----------------------------------------------------------------
7. DO NOT
----------------------------------------------------------------
- Do NOT add a calendar / Calendly embed.
- Do NOT add a chatbot or live-chat widget.
- Do NOT add a newsletter signup.
- Do NOT add additional social channels beyond the three
  canonical ones.
- Do NOT replace the Resend API with a third-party form
  service (Formspree, Netlify Forms, etc.).
- Do NOT show a captcha; the API route already rate-limits
  / validates inputs.

----------------------------------------------------------------
8. ASSUMPTIONS
----------------------------------------------------------------
- The Resend API route is already wired in
  src/pages/api/contact.js and works in production. If
  RESEND_API_KEY is missing in env, the route returns a
  500 — surface this in the UI as a generic "Couldn't
  reach the server" error.
- The form posts JSON, not form-urlencoded. axios handles
  this; the route reads req.body.
- The server may also send a notification email back to
  the user (an auto-reply). The UI's success state does
  not need to know about this; the existing copy ("Thanks
  — I'll reply soon.") already implies it.
- The email is displayed as plain text, not as a clickable
  link to a "subscribe" form. The mailto: link is fine and
  is the canonical pattern.
- "Replies within 48 hours" is the canonical response
  window. It is rendered as-is; do not infer shorter or
  longer windows.
- The hero's "Open to work" eyebrow is a status indicator,
  not a literal claim. If the user is later between roles,
  swap it to "Available for short engagements" or similar —
  but the default is "Open to work".
- The optional "Based in Lagos · UTC+1 · remote-first" line
  is informational only. If the user moves, update the
  AboutHero / ContactDetails copy together.
