0. WHAT THIS PAGE IS
----------------------------------------------------------------
Victor's AI Lab — an experimental playground. The page MUST feel
visually and tonally different from /projects:

  Projects page = engineered showcase.
  Lab page      = research notebook / laboratory.

Do NOT present experiments as production products. Failures are
allowed and visible. The hero copy is "Victor's AI Lab" and the
page must explicitly communicate "I'm not only building AI systems
— I'm actively exploring how they work."

Reference image: @docs/prototypes/LabUI.png
Reference doc:   @docs/LabUI.md

1. PAGE FILE
----------------------------------------------------------------
src/pages/lab.js (refactor — the orchestration currently lives
here; keep the orchestration but pull the render shapes into
the section components).

Default export LabPage().
State (local — no Redux):
  const [active, setActive] = useState("all");
  const [query,   setQuery]   = useState("");

Derived (useMemo):
  counts       = total + per-category counts from EXPERIMENTS.
  statusCounts = per-status counts from STATUS_LABELS keys.
  featured     = getFeaturedExperiment().
  filtered     = listExperimentsByCategory(active) excluding
                 featured.id.
  visible      = if query is empty → filtered; else filter
                 filtered by haystack of title + id + tech +
                 category (lowercased substring match).

Head:
  - title "Lab — Akinola Victor"
  - description "An experimental playground for exploring AI
                 systems, testing ideas, and learning through
                 building."

Body order:
  <PageShell>
    <LabHero counts={counts} statusCounts={statusCounts} />
    <FeaturedExperiment experiment={featured} />
    <ExperimentGrid experiments={visible} active={active}
                    onChange={setActive} counts={counts}
                    statusCounts={statusCounts}
                    query={query} onQueryChange={setQuery} />
    <LabManifesto />
  </PageShell>

3. DATA USAGE
----------------------------------------------------------------
- src/data/experiments.js exports CATEGORIES, STATUS_LABELS,
  EXPERIMENTS, getFeaturedExperiment, listExperimentsByCategory.
  Add to this file (do not remove anything):
    - export function getExperimentsCount() { return EXPERIMENTS.length; }
    - export function getStatusCounts() { /* iterate STATUS_LABELS */ }
- Each experiment record's `tech` array is shown as small
  mono chips, max 4 visible.
- Status dot colors are defined in STATUS_LABELS. Do not
  hardcode them in the component.

----------------------------------------------------------------
4. ANIMATION
----------------------------------------------------------------
- Oscilloscope: 5s loop, paused on reduced-motion.
- FeaturedExperiment: 0.5s ease power2.out on entry, no
  continuous animation.
- ExperimentGrid cards: 0.5s × stagger 0.06, once per card.
- Filter pill / search focus transitions: 200ms CSS.
- No hover-driven transforms on cards (different from the
  home focus cards — the lab is calmer).

----------------------------------------------------------------
5. RESPONSIVE BEHAVIOR
----------------------------------------------------------------
- < w7: 1 column everywhere, oscilloscope full width, search
  full width, filter pills wrap.
- w7 — w8: 2 col grid.
- ≥ w9: featured experiment is 5/7 split; grid is 2 col.

----------------------------------------------------------------
6. ACCESSIBILITY
----------------------------------------------------------------
- aria-label on the section, the filter region, the search
  region, the grid region.
- Empty state has role="status".
- The status dot is a span with aria-label={STATUS_LABELS[x].label}.
- Search input has both an aria-label and a visually-hidden
  <label> for screen readers.
- No information is conveyed by color alone (status text is
  always rendered).

----------------------------------------------------------------
7. DO NOT
----------------------------------------------------------------
- Do NOT add a "Featured" badge on experiment cards (only
  the page's single FeaturedExperiment block has it).
- Do NOT make the lab look like the projects page. Different
  framing, different cards, different status vocabulary.
- Do NOT add a sort dropdown.
- Do NOT add a "View project" button — experiments are not
  projects. The CTA on a card, if any, is a future per-
  experiment detail page that does not yet exist; render it
  disabled with a tooltip.

----------------------------------------------------------------
8. ASSUMPTIONS
----------------------------------------------------------------
- Status labels and their dot colors are defined in
  STATUS_LABELS in src/data/experiments.js. Do not redefine
  them inline.
- The seven CATEGORIES (all + 6) are defined in the data
  file; the filter row pulls from there.
- A future /lab/[id] route is not part of this scope. The
  "VIEW SPECIMEN" CTA on the featured experiment stays as a
  ghost button with a "coming soon" tooltip until that route
  exists.
- The lab page shares the global Navbar/Footer. No lab-
  specific chrome.
- Failures are first-class — experiments with status "failed"
  are rendered identically to "successful", with their status
  label visible.
- The FeaturedExperiment is excluded from the grid so the
  page always shows the same headline specimen and a clean
  chronological list below.
- Search is substring + case-insensitive against title, id,
  tech, and category only. It does NOT search question/
  experiment/result/learned text (the home page and /projects
  page are wider-search; lab search is narrow).
