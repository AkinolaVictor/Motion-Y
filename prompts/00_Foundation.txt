3. DESIGN SYSTEM (the contract every page must obey)
----------------------------------------------------------------
3.1 Visual language
   - Default mode: DARK. (The useThemeToggle hook defaults to "dark";
     no stored choice → "dark".)
   - Palette (already defined as CSS vars in globals.css — DO NOT
     change the hex values; if you add tokens, add them next to these):
       dark (default):
         --bg-base: #0a0a0a       (page background)
         --bg-surface: #101010    (cards, nav scrolled state)
         --bg-elevated: #161616   (hovers, mobile nav active)
         --bg-card: #161616
         --text-primary: #ededed
         --text-muted: #8a8a8a
         --border-subtle: #1f1f1f
         --accent: #7cf6c0        (electric mint — calm, not acid green)
         --accent-dim: #2a4a3d
         --accent-fg: #0a0a0a
       light (toggled via .light class on <html>):
         --bg-base: #f5f5f4
         --bg-surface: #ffffff
         --bg-elevated: #ffffff
         --bg-card: #ffffff
         --text-primary: #0a0a0a
         --text-muted: #52525b
         --border-subtle: #d4d4d8
         --accent: #0f8a64
         --accent-dim: #c7f0e2
         --accent-fg: #ffffff
   - Three theme modes: dark / light / system. Cycle order
     dark → light → system → dark (already implemented in
     useThemeToggle; do not change it).
   - One accent color. No gradients as decoration, no glassmorphism,
     no neon, no stock AI imagery, no robots, no generic templates.
   - Aesthetic: "near-black/charcoal + soft-white typography + muted
     gray text + one accent". Dark first, light as a considered
     secondary mode, system as the third.

3.2 Typography
   - Display: .dmd (DM Serif Display) — used sparingly, mostly for
     editorial / pull-quote / large feature moments.
   - Headings: .overpass (Overpass) — for ALL h1/h2/h3, hero titles,
     section titles, project / article names. weight 600, tracking
     -0.02em on huge display, -0.01em on small, leading 1.02–1.05
     on display, 1.25–1.4 on smaller headings.
   - Body: .noto (Noto Sans) — for paragraphs and UI text. default
     14–15px, leading 1.6–1.7.
   - Mono / metadata: .mono (ui-monospace / JetBrains Mono) — for
     eyebrows, code, status, dates, technical captions, terminal
     frames. Use uppercase + tracking 0.18–0.22em + size 10–12px.
   - .dmd / .overpass / .mono are already utility classes in
     globals.css — reuse them, do not redefine.

3.3 Spacing & layout
   - Use FLEXBOX for every page / section / component layout
     (per dev_rules.md). CSS grid is acceptable ONLY for explicit
     2D layouts (page section splits, the contact band, the hero
     left/right split, the project detail hero). Document every
     grid use with a short comment.
   - Page max width: 1200px. Outer container is <Container> with
     responsive horizontal padding: px-6 → w7:px-10 → w9:px-14.
   - Section vertical rhythm: py-20 → w9:py-28 (or 16/24/28 for
     hero). Use hairline (1px gradient) or border-b on
     var(--border-subtle) to separate sections.
   - Breakpoints (already defined in @theme in globals.css):
       w4 400, w5 500, w6 600, w7 728, w8 800, w9 900,
       w10 1000, w11 1100, w12 1200
     Mobile-first; switch major layouts at w7 (728) and w9 (900).
     Nav collapses to hamburger at w7; Contact band becomes
     2-col at w9.

3.4 Components to ship in primitives/
   - Button
       Variants: primary (accent fill), ghost (border only),
                 icon (square, bordered).
       Sizes: sm (h-9), md (h-11), lg (h-12).
       Renders <a> if href is provided (external opens _blank
       rel=noreferrer noopener); <button> otherwise.
       Hover: -translate-y-[1px] + soft accent shadow.
       Focus-visible: ring-2 ring-accent ring-offset-2.
   - Container (already exists — keep API: as, className, children).
   - Pill — small mono tag with two variants (default / accent).
   - SectionHeader — eyebrow (mono, "01 / FOCUS") + title
     (.overpass, clamp(2rem,4vw,3rem)) + optional lead paragraph.
     align: "left" | "center".
   - Portrait — small circular byline avatar (40px default), used on
     project & article heroes. Props: size, src (default /me.jpg),
     name, showByline.

3.5 Primitives to keep stable
   - PageShell: flex column with Navbar + <main>{children}</main> + Footer.
   - Navbar (already implemented — DO NOT rewrite, just verify):
     brand mark with pulsing accent dot, 6 links (Home, Projects,
     Lab, Writing, About, Contact), theme toggle (cycle), "Let's
     talk" CTA, mobile drawer at w7.
   - Footer: copyright, "Built with Next · React · GSAP" tag,
     3 social icon buttons (GitHub, LinkedIn, Email).
   - The 3 social links the user confirmed as canonical — use
     these EVERYWHERE socials appear (Navbar, Footer, Contact,
     About /social, Project hero CTAs are NOT social, but anything
     that says "find me on" must use these):
       GitHub:    https://github.com/AkinolaVictor
       LinkedIn:  https://www.linkedin.com/in/victoral/
       X:         https://x.com/MoreThanAVictor
       Email:     mailto:akinolavictor50@gmail.com
     Do not invent a new "X / Twitter" handle anywhere.

3.6 Motion system
   - Only GSAP. No Framer Motion, no CSS keyframes beyond the two
     already in globals.css (accent-pulse and the .bg-grid backdrop).
   - All section reveals use the .revealOnScroll(scope, "[data-reveal]")
     helper or the same pattern (gsap.context, from autoAlpha+y,
     ScrollTrigger once, ease power2.out, start "top 85%").
   - Maximum duration: 5s. Most: 0.4–0.7s. Stagger: 0.05–0.10s.
   - Honor prefers-reduced-motion at every gsap call:
       if (window.matchMedia("(prefers-reduced-motion: reduce)").matches) return;
     The revealOnScroll helper already does this — keep doing it
     everywhere else.
   - Page-load micro-intros (hero char stagger, eyebrow pulse) are
     allowed but must be < 1.5s total.
   - Use gsap.context + cleanup ctx.revert() on unmount.

3.7 Accessibility
   - All interactive elements reachable by keyboard, visible focus
     ring (already in globals.css :focus-visible).
   - Every <section> gets an aria-label or aria-labelledby.
   - Every <img> gets meaningful alt. Decorative → alt="" + aria-hidden.
   - Color contrast meets AA in both dark and light modes.
   - All form fields have associated <label>s (use the Field
     primitives in ContactForm as the pattern).
   - The theme toggle exposes what pressing it WILL do
     (aria-label = "Theme: dark. Click to switch to light mode.").

3.8 Performance budget
   - All images use loading="lazy" (eager for the home hero avatar).
   - Decode async. Provide width + height to prevent CLS.
   - Hero, fonts, and /me.jpg are preconnected or preload where
     they appear above the fold.
   - No client-side state for theme beyond what useThemeToggle
     already does; do not lift filter / search state into Redux.

4. SEPARATION OF CONCERNS (dev_rules.md)
----------------------------------------------------------------
- Each page lives in src/pages/<route>.js. Route = file. No shared
  page file.
- Each SECTION of a page is its own file inside
  src/components/<pageArea>/. The page file only imports and
  composes section components.
- Primitives live in src/components/primitives/ and are reused
  across pages.
- Data (projects, articles, experiments, about copy, contact copy)
  lives in src/data/*.js. Section components import from data/.
  No copy hardcoded inside components unless it is decorative.
- Only add a new folder under src/components/ when there is a real
  new section family. Currently the families are: home, projects,
  projectDetail, writing, articleDetail, about, lab, contact.
- Utilities / pseudo functions go in src/utils/. Pseudocode-style
  helpers (cn, formatters) only.
- No global state or slice unless truly necessary. Filter/search
  state stays local to the page.

5. BUILDING PRINCIPLES (dev_rules.md)
----------------------------------------------------------------
- Use FLEXBOX for each page/section/component layout. Avoid unless
  necessary.
- Each component file begins with a 2–4 line comment block
  describing purpose, props, and any non-obvious behavior.
- File names are PascalCase for components (Hero.jsx), camelCase
  for hooks (useThemeToggle.js), camelCase for data and utils
  (projects.js, cn.js).
- Components that use GSAP wrap in gsap.context + cleanup.
- Every component file uses the relative import paths
  ../primitives/X or ../../utils/cn — do not alias.
- Tailwind v4 — declare tokens via @theme in globals.css; do not
  add a tailwind.config.js (the project intentionally uses the
  v4 CSS-only config).

----------------------------------------------------------------
6. WRITING PRINCIPLES (copy / voice)
----------------------------------------------------------------
- Voice: technical, confident, calm. First person ("I build…",
  "I've been…"). Not boastful, not apologetic.
- Sentence-level rules:
    - No exclamation marks except in CTAs.
    - No "just", "really", "very" filler.
    - No emoji in body copy (eyebrow labels in lab/projects may
      use a single 🧪 because the design uses it, but stop after
      that).
    - Numbers in mono when they are technical (latency 1.4s, p95
      etc.) but normal in prose.
- Headlines: short, declarative, period at the end ("Projects.",
  "Lab.", "About."). Multi-word display titles also end with a
  period.
- Section eyebrows: 2-digit index + slash + ALL-CAPS mono label
  ("01 / IDENTITY", "02 / FOCUS", "03 / WORK").
- CTAs: verb + noun. "Explore Projects", "Send message", "Read
  case study", "Read Article". Arrow is a unicode → not →, used
  inline next to the verb.
