0. WHAT THIS PAGE IS
----------------------------------------------------------------
An editorial, technical showcase of every project, not a marketing
gallery. It is paired with /projects/[slug] (the case study).

Two filters: a CATEGORY pill bar AND a SEARCH input. The search
takes priority when a query is present (it ignores the active
category and matches across slug, name, tagline, description,
tags, labels, categories, and year).

Reference image: @docs/prototypes/ProjectsUI.png
Reference doc:   @docs/ProjectUI.md
Live reference:  https://ai-port-test.vercel.app/projects

1. PAGE FILE
----------------------------------------------------------------
src/pages/projects/index.js

Default export ProjectsPage() component.
State (local to the page — do NOT put in Redux):
  - const [active, setActive] = useState("all");
  - const [query,   setQuery]   = useState("");
  - const searchId = useId();

Head:
  - title "Projects — Akinola Victor"
  - description "A collection of AI systems, experiments and
                 developer tools by Akinola Victor."

Layout, top → bottom:
  - <PageShell>
  - <ProjectsHero
       counts={counts}
       active={active}
       onChange={setActive}
       searchId={searchId}
       query={query}
       onQueryChange={setQuery} />
  - <section aria-label="Project list" border-b>
      <Container>
        {visible.length === 0 ? (
          <div className="py-16 text-center">
            <p className="mono text-[12px] uppercase tracking-[0.2em]
                          text-[var(--text-muted)]">
              {query
                ? `No projects match "${query.trim()}" — try another term.`
                : "Nothing in this category yet — try another."}
            </p>
          </div>
        ) : (
          <ul className="flex flex-col">
            {visible.map((p, i) => (
              <li key={p.slug}>
                <ProjectListItem project={p} index={i} />
              </li>
            ))}
          </ul>
        )}
        <div className="hairline mt-2" />
      </Container>
    </section>
  - <ProjectsBio />

The two big data computations:
  counts = useMemo(() => {...all count + per-category counts});
  filtered = useMemo(() => listProjectsByCategory(active), [active]);
  visible  = useMemo(() => {
    const q = query.trim().toLowerCase();
    if (!q) return filtered;
    return filtered.filter(p => {
      const hay = [p.slug, p.name, p.tagline, p.description,
                   ...(p.tags ?? []), ...(p.labels ?? []),
                   ...(p.categories ?? []), String(p.year ?? "")]
        .join(" ").toLowerCase();
      return hay.includes(q);
    });
  }, [filtered, query]);

8. ASSUMPTIONS
----------------------------------------------------------------
- The "search bar before all the projects are listed, just below
  the initial brief groups on top" correction (textme.txt) means
  the search input is positioned AFTER the eyebrow + title + lead
  + filter pills, and BEFORE the project list. Not at the very
  top of the page, not inside the navbar.
- The filter pills are CATEGORY only — not search. The search
  input is its own control. When both are active, search wins
  (the active category is preserved in state but ignored for
  matching).
- The grep prefix on the search input is a stylistic choice (it
  matches the terminal-style eyebrow on the rest of the site).
  "esc" is the standard keyboard mnemonic to clear; do not bind
  a global key listener — the button is enough.
- /projects/[slug] (the next prompt) consumes PROJECTS via
  getProjectBySlug(slug). No API changes are needed here.
- The list is rendered ungrouped (no "2024 / 2025 / 2026"
  headers). The list ordering (year desc) is enough.
- Featured / Experimental / Open Source labels are shown via the
  status dot in ProjectListItem — no separate "Featured" badge
  is added in this view.
- Search matches are case-insensitive substring (not regex).
